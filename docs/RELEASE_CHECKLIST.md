# Чек-лист релиза HexTactics

Порядок и команды — `CLAUDE.md`, раздел «Версии и релизы». Перед тегом каждой версии:

- [ ] Версия совпадает в `Directory.Build.props` и `src/GodotClient/project.godot`.
- [ ] `dotnet build HexTactics.sln` без предупреждений, `dotnet test HexTactics.sln` — все зелёные.
- [ ] Регрессионный сценарий новой версии добавлен в `tools/verify_release.ps1` и проходит из исходников.
- [ ] Обновлены `CHANGELOG.md`, `README.md`, `docs/ARCHITECTURE.md`, `docs/CONTROLS.md`, `docs/DECISIONS.md` (решения и «Миграции»),
      `docs/CONTENT_FORMAT.md`; при изменении схемы пользовательских данных — `docs/MIGRATIONS.md` и миграция с резервной копией.
- [ ] Создан `docs/releases/vX.Y.Z/README.md`.
- [ ] **Правило ТЗ ч.4 §9.3** — для каждой новой редактируемой механики выполнено всё сразу:
  1. правила описаны в актуальном ТЗ (или в `docs/DECISIONS.md`, если это проектное решение);
  2. создана/расширена версионированная схема определения;
  3. есть проверка значений и миграция старых данных;
  4. подключён единый обработчик в симуляции (`EffectResolver` / система тика), без второй реализации формул;
  5. поля и предпросмотр зарегистрированы в режиме «Разработчик» (реестр полей/эффектов);
  6. работают сохранение, импорт и экспорт;
  7. есть тесты: игровое действие, UI-редактирование, загрузка, совместимость, откат.
  Новые категории — только через реестр, существующие объекты и их стабильные ID сохраняются.
- [ ] Коммит → аннотированный тег → `tools/build_release.ps1` → `tools/verify_release.ps1 -Run` (Windows-сборка, Wine).
- [ ] Отдельный коммит: архив `release_archives/vX.Y.Z/`, скриншот `docs/releases/vX.Y.Z/screenshot.png`; push ветки.
- [ ] Старые архивы, теги, исторические редакции ТЗ и пользовательские данные (`user://`) не тронуты.
